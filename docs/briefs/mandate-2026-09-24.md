## M1 — Rendering: a post-processing API

- [x] `Lighting` gains the post chain's controls: bloom on/off, intensity and
      threshold; automatic exposure on/off. A 2D game turns bloom off and its
      sprites stop glowing. **Folded into ADR 0096** (2026-09-24): bloom becomes
      a `BloomEffect` instance and `AutoExposure` a `Lighting` property, built
      and ticked by `docs/briefs/atmosphere-post-kickoff.md` (Stages 2 and 7).
      **Done** (2026-09-25): a disabled `BloomEffect` under `Lighting` turns
      `examples/20-platformer`'s glow off (Stage 2, captured), and
      `Lighting.AutoExposure` landed with ADR 0096's other four `Lighting`
      properties (Stage 7).

## M2 — Terrain: the one-sided skirt

- [x] A terrain node's skirt hangs only on the side that faces a coarser
      neighbour, not on all four. That removes the skirt a camera inside the
      ground could see. **Done** (2026-09-25): the mesher files each side's
      skirt as a section of its own (`TerrainMesh::sectionSides`), the loader
      works out which sides of each drawn node meet a coarser drawn node
      (`terrainSkirtSides`), and extraction leaves the other skirts out. No
      re-mesh when a neighbour changes level: the choice is made per draw.

## M3 — 2D depth

- [x] 2D joints for scripts: a hinge, a spring (distance joint with stiffness
      and damping) and a weld, between two `Part2D`s, through the same
      `IPhysics2D` seam. ADR 0102: `HingeConstraint2D`, `SpringConstraint2D`,
      `WeldConstraint2D`.
- [x] Sprite animation: a component that plays frames of a sprite sheet on the
      sim clock, so a walk cycle is data instead of script. ADR 0102:
      `SpriteAnimator`.

## M4 — 2D on the wire, completed

- [x] Replicated sprites are interpolated between snapshots, as a
      `BasePart`'s `CFrame` is. ADR 0103.
- [x] A tilemap's live edits travel as a message, so a level built or broken
      during play is the same on every machine. ADR 0103: `Tilemap2D` is
      replicated, its cells in `TilemapBlocks`, protocol 15.

## M5 — Navigation depth

- [x] More than one agent size: a mesh per agent type, named, chosen per query.
- [x] Area costs: parts can mark ground as costly or forbidden (water, mud,
      a door that is shut).
- [x] Off-mesh links: a jump or a ladder between two points the mesh does not
      join.
- [x] Crowds with local avoidance, over the vendored DetourCrowd: agents that
      walk their paths without walking through each other.
- [x] 2D navigation: paths on the plane, over a tilemap's open cells and
      `Part2D` obstacles.

## M6 — Multiplayer depth

- [x] `Team`: a player's side, replicated, with a colour and a name.
- [x] Network ownership: the authority can hand simulation of a part to one
      player, so what that player pushes moves without a round trip.
- [x] A public, versioned protocol: the wire format written down as a
      specification, generated from the schema, with a compatibility policy.
- [x] Rollback: the world rewound to a tick and re-simulated with corrected
      input, building on the level-C determinism and the character replay
      that already exist.
