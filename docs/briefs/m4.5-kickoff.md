# M4.5 Kickoff — Correcting the World: the Environment the Renderer Never Read

- Started: 2026-08-20
- Roadmap section: docs/roadmap.md#m45--correcting-the-world-the-environment-the-renderer-never-read-s

## Goal (restated)

M4 built a renderer and then certified it against its own defaults. `Lighting`
was never reachable from the frame, so every image the gate recorded — the six
capture goldens, the lavapipe screenshot, the 1080p baseline — describes a sun
pinned straight up over a scene that asked for a sun at 8 a.m. This milestone
makes the frame read the world it is drawing, proves it with a check that could
not have passed while the defect existed, and then re-records everything M4
measured against the wrong picture. Along the way it pays off the rest of the
defects one afternoon of a human using the engine turned up: a `Transparency`
that switches instead of fading, a shadow grid that crawls, properties that
accept a write and do nothing, and an engine that dies without leaving a trace
of why.

The through-line is one sentence, and it is why this is a milestone rather than
a patch: **M4's gates asserted against artifacts the engine produced, never
against the description the engine was given.** Every scope item below either
fixes an instance of that or makes the next instance visible.

## NOT in scope

Named so a later reader knows each was decided rather than forgotten.

1. **Order-independent transparency.** Sorting is per draw, so two transparent
   surfaces that intersect each other sort wrongly where they cross. The roadmap
   says this explicitly and says it is not on the v1 list.
2. **Transparent shadows.** A half-transparent part still occludes fully; the
   shadow pass keeps drawing everything.
3. **The rotational half of the shadow flicker.** A sun that turns rotates its
   own texel grid, which snapping cannot fix; that needs a normal-offset bias
   and a comparison sampler. Visible only while `ClockTime` moves, and the
   roadmap excludes it here.
4. **Shadow cascades.** One cascade, from the sun, as M4 shipped.
5. **Shadows from punctual lights.** That is what makes `PointLight.Shadows`
   inert; rendering it is a later milestone's work.
6. **IBL / ambient probes.** A metal is still lit by punctual lights and the
   flat ambient.
7. **Clustered light culling.** Still eight lights per draw.
8. **The `Sky` class**, `Camera.ViewportSize`, `MeshPart.CollisionFidelity` —
   still declared nowhere, for M4's reason: they are not implemented.
9. **Alpha cutout.** The human replaced it with the blended pass. `AlphaCutoff`
   stays in the material block where the importer writes it, unused by this pass.
10. **A general "who reads this property" analysis.** The inert marker is a
    declaration in the IDL, checked by review, not something derived from C++ by
    a tool.
11. **Symbolizing crash dumps, or uploading them anywhere.** The handler writes a
    minidump and says where. Reading it is a developer's job with a debugger.
12. **A crash handler on Android.** Desktop tiers only; the phone's own tombstone
    is what exists there, and the milestone that ships to a phone can revisit it.
13. **Reparenting or instance creation from the inspector.** Still out, as in M4.
14. **The clang-format gate.** Still the first act of M5, on a quiet tree.
15. **M5's physics, and anything a physics demo would need.**

## Decisions

1. **`Lighting` becomes a boot service, beside `Workspace` and `ScriptService`.**
   Not a lazy re-resolve on each miss. The rule `services.cpp` states — "created
   by its first `GetService`" — cannot be true of a service the frame reads every
   tick whether or not a script ever mentions it. Fixing the cache instead would
   leave the same trap one refactor away, which is the roadmap's own reasoning.
2. **The creation is guarded on the class existing**, because `Lighting` is
   registered by `render` and an engine built without that module has no such
   class. A guard rather than an assert: `registerServices` lives in `script` and
   must not acquire an opinion about which modules are compiled in.
3. **`api-design.md` §1.2 changes in the same commit** (§5: docs follow
   reality). The list of boot services is public surface and is wrong by
   omission.
4. **The proof is a differential, not a golden.** Two frames whose only
   difference is a `Lighting` value must produce different bytes. A golden can
   only say "the same as last time", which is exactly what it said while this was
   broken. Three levels: a unit assertion that the snapshot's environment equals
   what the world holds, a host test that the id resolves, and a CTest that
   renders one scene at two clock times and requires the streams to differ.
5. **Transparency rides in `GpuObjectUniforms`**, which is already per draw and
   already bound per draw. Not the material block: materials are deduplicated per
   frame so the sort key can group draws by bind set, and a per-instance alpha
   there splits one material into as many as there are distinct values. ADR 0037
   froze the RHI *calls*; this adds none.
6. **The transparent pass is a second pipeline over the same draw list**, run
   after the opaque one with depth-test on, depth-write off and source-alpha
   blending. `BlendState` already exists in `rhi/descs.h` and the SDL_GPU backend
   already honours it, so the freeze is untouched here too.
7. **Back-to-front ordering is `extract`'s**, expressed in the existing
   `sortKey`: pass 1 for transparent, and the depth field inverted so ascending
   key order is descending view depth. Inverting at extraction rather than
   reversing at submission keeps "walk the list in order" true in every backend,
   which is M4's third design constraint.
8. **A draw is transparent when its instance alpha or its material's base-colour
   alpha is below one.** Both, because a glTF material can be transparent on its
   own and a script can make an opaque mesh see-through; either alone leaves a
   case that renders wrong.
9. **Shadow snapping is in light space, at texel granularity.** Extent and
   resolution are compile-time constants, so the increment is one too. The box is
   centred on the camera, which sits at the snapshot's origin, so what is snapped
   is the light-space position of that origin.
10. **`PointLight.Shadows` and `SpotLight.Shadows` stay, marked inert.** Removing
    them would break a familiar shape for a property whose semantics are not in
    doubt — only its implementation date is. What was actually wrong is that
    nothing told the person clicking it. That is Decision 11.
11. **The IDL gains `Inert`**, a property-level declaration meaning "backed,
    stored, read back faithfully, and nothing acts on it yet". It flows to
    `PropertyDesc`, to the inspector as a visible tag, and to the api-dump. The
    schema requires `Native` alongside it, because a property with no `Native` is
    already declared-not-backed and two markers for one idea would confuse.
12. **`Model.PrimaryPart` is not inert, and the ledger was wrong about it.**
    `instance_binding.cpp`'s `modelPivot` reads it: with a primary part
    `GetPivot` returns that part's `CFrame` and `PivotTo` moves the model about
    it. The finding is that nobody had tested the consuming branch, so the
    property looked unread from every angle anyone checked. A test, not a marker.
13. **The log file sink's path is injected by `app`.** `core` is L0 and
    `platform::paths()` is L1. The console sink is unchanged and the file is an
    addition: every gate and the conformance runner read stdout.
14. **The crash handler lives in `platform`**, for the same reason the SDL seam
    does — it is per-OS code — and is installed by `app` at boot.
15. **Human-reported defects get a numbered registry, `docs/defects.md`**, and
    the docs gate enforces that the numbering has no holes. That is what makes
    losing one visible: a close-rewrite of `PROGRESS.md` can drop a bullet, and it
    cannot drop a row without leaving a gap the gate names.
16. **The deliverable gains one transparent object.** The roadmap's "unchanged as
    source" means the fix is the engine's rather than the example's; it cannot
    mean the deliverable demonstrates a fade with nothing that fades.

## Attempted / abandoned

- **Reproducing D004 by fuzzing the inspector's write path.** Driving `Size` and
  `CFrame` through zero, negative, 1e30 and infinity for 32 frames, each value
  read back the way the widget reads it, applied through `Inspector::enqueue` and
  the FrameStart drain, with a render extraction every frame. It does not crash.
  Kept as a test rather than deleted: ruling the write path out is most of what
  is known about that defect.
- **Reproducing D004 by defocusing the window.** 25 minimize/restore cycles over
  900 windowed frames, driven from PowerShell. Exit 0, no dump. The human's note
  that the crash "may have coincided with the window losing focus" is not
  contradicted by this — a defocus during a drag is a third thing — but the
  defocus path on its own is clean.
- **Recording uniform block CONTENTS in the capture stream, byte for byte.**
  Rejected in favour of a digest: 96 binds a frame at 48 to 132 floats each is a
  40 KB golden per six frames, and every one of those numbers is a float that
  MSVC and Clang may disagree about in the last bit. The digest quantizes onto
  the four-decimal grid the stream already uses, which is the same tolerance
  `real` has and no more. Verified byte-identical across both tiers.
- **A `--fixed-camera` environment switch on `examples/02-meshes`.** The first
  attempt at the day strip read `os.getenv` from the example's script, which is a
  sandbox hole (R4) for a convenience. The strip has its own scene instead, the
  same way the capture gate has its own copy, and for the same reason: evidence
  that reaches into an example breaks when someone edits the example.

## Findings

1. **The blocking render gate recorded how many bytes a uniform block was and
   never what was in it.** Every matrix, every light, every material colour a
   frame carries goes through `bindUniforms`, so the gate could see the *shape*
   of a frame and nothing about its content. That is why six goldens across three
   camera angles and two lighting states were green for a milestone while the sun
   stood still. Tenth instance of a gate that passes while doing nothing in this
   project's life, and the most expensive: it certified a milestone.
2. **A golden cannot detect a defect that was present when it was recorded.**
   This is obvious written down and was not obvious in practice, because a golden
   *feels* like an assertion about correctness. It is an assertion about
   stability. The differential — change one input the output must depend on, and
   require the output to change — is the shape that catches this, and it costs
   one CTest.
3. **The test was at the wrong level, and the level it was at was the easy one.**
   `render_world_tests` built a `Lighting` instance itself and handed the id
   straight to `extract`. Every environment assertion passed against an id the
   host never produces. The untested step was the one that resolved the id, which
   is the step that was broken — and it was untested because testing it needs a
   host, which is more work than constructing a component.
4. **The renderer's own defaults hid the defect for a milestone.**
   `RenderEnvironment` has sensible defaults, so an unresolved `Lighting` looked
   like a lit scene rather than a black one. A default that is *plausible* is
   worse than one that is obviously wrong, because nothing ever asks about it.
5. **The debug path had been drawing in the wrong space since M4**, and the debug
   path is what a person reaches for when the real one is not working. World
   coordinates through a camera-relative view-projection displaced every wire box
   and every `DebugService` line by the camera's distance from the origin. Found
   by looking at a screenshot, not by any test — the boxes were *present*, and a
   test that counts them passes.
6. **The tail carried the defect and the median never noticed.** Re-measuring at
   1080p moved the median not at all (0.46 ms then and now, with a whole extra
   pass) and the worst frame from 2.06 ms to 1.79 ms — on two cores from 6.65 ms
   to 1.77 ms, a factor of four. The shadow grid sliding every frame was costing
   the tail and nothing else. A perf gate that watches only the median would have
   watched this defect arrive and leave.
7. **An audit scoped to one module is not an audit.** The M4-era sweep that
   "found" `Model.PrimaryPart` unread searched `engine/render` for a value
   consumed in `engine/script`. The retraction is in the roadmap and the register
   rather than deleted, because the useful artifact is the shape of the mistake.
8. **A property can be backed, stored, read back faithfully, and still be a
   lie.** All three of this project's unbacked-behaviour reports came from a human
   changing a value and watching nothing happen, and in each case the engine was
   behaving exactly as designed. `Inert` in the IDL and "(stored)" in the panel is
   the whole fix, and it is a documentation fix wearing a code fix's clothes.
9. **`schema.luau` had `Native` backwards** — absent meaning "not backed", when
   the generator derives the name from the class and `Native = ""` is the way to
   say unbacked. Taken literally, the stale paragraph made every property in the
   IDL unbacked, including the ones nine hundred conformance cases exercise. A
   doc that is wrong in a way nothing can execute stays wrong indefinitely.
10. **`fopen_s` opens for exclusive access.** Nothing could have read the engine's
    log while it ran, which is most of why a person wants one. Found only because
    the test read the file while it was still open — an assertion written to prove
    the per-line flush, which caught a different bug entirely.
11. **A crash handler is untestable in-process by construction**, so it needs its
    own process. `luaug_crash_probe` faults on purpose and a CMake driver checks
    the artifact. Without that, the handler would have been a feature verified by
    reading it, with a failure mode of "the human hits the crash it was written
    for and still has nothing to send".
12. **Six test fixtures initialised `PropertyDesc` positionally** and stopped
    compiling the moment it grew a field. That is the good outcome; the bad one
    was available, and would have been a new `bool` landing in an accessor slot
    because the types happened to line up.
13. **`PivotTo` was the deprecated call under the new name.** Without
    `PivotOffset` a pivot is always an object's centre, so `Model:PivotTo(cf)` is
    `PrimaryPart.CFrame = cf`. It passed its tests, because its tests asked
    whether the model moved. Nobody asked whether a door could hinge.
14. **A comment and its code had disagreed for two milestones about what a
    model's pivot is** — "the centre of the extents box" against an average of
    part positions, a different point whenever parts differ in size, with the real
    box computed a few lines below in the same file.
15. **The example's own scene could not demonstrate the property it was meant
    to.** `Transparency` is per instance and `examples/02-meshes` was a single
    `MeshPart`, so there was nothing to set it on. The deliverable had no way to
    show the defect even if someone had looked for it.
16. **Two artifacts is one file too many for a claim about time.** The day strip
    exists because the milestone's claim — the sun crosses, shadows lengthen, a
    pane fades — cannot be carried by a screenshot, and a folder of eight
    numbered PNGs makes the reviewer assemble it. Fifty lines of `imgstrip`.
17. **`luaug_net_tests` hung once**, holding CTest for the full ten-minute
    timeout, and passed on a re-run. Recorded as D018 rather than shrugged at:
    §12 quarantines on the *second* occurrence, and a first occurrence nobody
    wrote down is a second occurrence that looks like a first.

### The deliverable, verified by looking at it

`docs/images/daystrip.png` — `examples/02-meshes`'s scene from a fixed camera,
one frame every three hours across a day, laid side by side by `imgstrip`. It is
the only form in which this milestone's claim can be checked at a glance, because
the claim is about change over time:

- **The sun crosses.** Dawn on the left, midday brightness in the middle, night
  on the right. Under M4 every frame of this strip was identical.
- **Shadows lengthen and sweep.** The cubes' shadows are short near noon and
  stretch across the ground towards evening.
- **The pane fades.** Nearly clear at midnight, most solid at midday, and every
  value in between is rendered — which is the whole difference from a cutout, at
  which 0.4 is fully opaque and 0.6 is gone.
- **The lamp's point light shows at night**, as a warm pool on the ground, which
  is the punctual path still working when the sun is not.

And the human's own reproduction, run again: `examples/02-meshes` with
`Lighting.Ambient` set to pure red against the ambient it ships now hashes
`6a31e3f0…` against `36fbc231…`. It hashed identically before this milestone,
which was the proof the defect existed.

### What the gates cost, and what they caught

- **The blocking render gate could not see a uniform's contents.** It recorded
  the byte count. Every matrix, light and material colour a frame carries goes
  through that call, which is why six goldens were green while the sun stood
  still. Fixed, and the fix immediately paid for itself twice: the shadow-snapping
  change moved 102 lines of the golden, and the transparent pass moved it again.
- **The crash handler needed its own process to be testable at all**, and the
  gate that tests it was verified by removing the handler's installation and
  watching it go red. Without that it would have been a feature verified by
  reading it, whose failure mode is a human hitting the crash it was written for
  and still having nothing to send.
- **The defect register's three checks were each broken on purpose**: a deleted
  row, an invalid state, and a citation with no row. All three reported.
- **The perf tail, not the median, was carrying the defect.** Re-measuring moved
  the median not at all and the worst frame by a factor of four on two cores.
- **`luaug_net_tests` hung once** and held CTest for its full timeout; a re-run
  passed. Recorded as D018 so a second occurrence is countable rather than
  looking like a first.
