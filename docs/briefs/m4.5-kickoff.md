# M4.5 Kickoff — Correcting the World: the Environment the Renderer Never Read

- Started: 2026-08-20
- Roadmap section: docs/roadmap.md#m45--correcting-the-world-the-environment-the-renderer-never-read-s

## Goal (restated)

M4 built a renderer and then certified it against its own defaults. `Lighting`
was never reachable from the frame, so every image the gate recorded — the six
capture goldens, the lavapipe screenshot, the 1080p baseline — describes a sun
pinned straight up over a scene that asked for a sun at 8 a.m. This milestone
makes the frame read the world it is drawing, proves it with a check that could
not have passed while the defect existed, and then re-records everything M4
measured against the wrong picture. Along the way it pays off the rest of the
defects one afternoon of a human using the engine turned up: a `Transparency`
that switches instead of fading, a shadow grid that crawls, properties that
accept a write and do nothing, and an engine that dies without leaving a trace
of why.

The through-line is one sentence, and it is why this is a milestone rather than
a patch: **M4's gates asserted against artifacts the engine produced, never
against the description the engine was given.** Every scope item below either
fixes an instance of that or makes the next instance visible.

## NOT in scope

Named so a later reader knows each was decided rather than forgotten.

1. **Order-independent transparency.** Sorting is per draw, so two transparent
   surfaces that intersect each other sort wrongly where they cross. The roadmap
   says this explicitly and says it is not on the v1 list.
2. **Transparent shadows.** A half-transparent part still occludes fully; the
   shadow pass keeps drawing everything.
3. **The rotational half of the shadow flicker.** A sun that turns rotates its
   own texel grid, which snapping cannot fix; that needs a normal-offset bias
   and a comparison sampler. Visible only while `ClockTime` moves, and the
   roadmap excludes it here.
4. **Shadow cascades.** One cascade, from the sun, as M4 shipped.
5. **Shadows from punctual lights.** That is what makes `PointLight.Shadows`
   inert; rendering it is a later milestone's work.
6. **IBL / ambient probes.** A metal is still lit by punctual lights and the
   flat ambient.
7. **Clustered light culling.** Still eight lights per draw.
8. **The `Sky` class**, `Camera.ViewportSize`, `MeshPart.CollisionFidelity` —
   still declared nowhere, for M4's reason: they are not implemented.
9. **Alpha cutout.** The human replaced it with the blended pass. `AlphaCutoff`
   stays in the material block where the importer writes it, unused by this pass.
10. **A general "who reads this property" analysis.** The inert marker is a
    declaration in the IDL, checked by review, not something derived from C++ by
    a tool.
11. **Symbolizing crash dumps, or uploading them anywhere.** The handler writes a
    minidump and says where. Reading it is a developer's job with a debugger.
12. **A crash handler on Android.** Desktop tiers only; the phone's own tombstone
    is what exists there, and the milestone that ships to a phone can revisit it.
13. **Reparenting or instance creation from the inspector.** Still out, as in M4.
14. **The clang-format gate.** Still the first act of M5, on a quiet tree.
15. **M5's physics, and anything a physics demo would need.**

## Decisions

1. **`Lighting` becomes a boot service, beside `Workspace` and `ScriptService`.**
   Not a lazy re-resolve on each miss. The rule `services.cpp` states — "created
   by its first `GetService`" — cannot be true of a service the frame reads every
   tick whether or not a script ever mentions it. Fixing the cache instead would
   leave the same trap one refactor away, which is the roadmap's own reasoning.
2. **The creation is guarded on the class existing**, because `Lighting` is
   registered by `render` and an engine built without that module has no such
   class. A guard rather than an assert: `registerServices` lives in `script` and
   must not acquire an opinion about which modules are compiled in.
3. **`api-design.md` §1.2 changes in the same commit** (§5: docs follow
   reality). The list of boot services is public surface and is wrong by
   omission.
4. **The proof is a differential, not a golden.** Two frames whose only
   difference is a `Lighting` value must produce different bytes. A golden can
   only say "the same as last time", which is exactly what it said while this was
   broken. Three levels: a unit assertion that the snapshot's environment equals
   what the world holds, a host test that the id resolves, and a CTest that
   renders one scene at two clock times and requires the streams to differ.
5. **Transparency rides in `GpuObjectUniforms`**, which is already per draw and
   already bound per draw. Not the material block: materials are deduplicated per
   frame so the sort key can group draws by bind set, and a per-instance alpha
   there splits one material into as many as there are distinct values. ADR 0037
   froze the RHI *calls*; this adds none.
6. **The transparent pass is a second pipeline over the same draw list**, run
   after the opaque one with depth-test on, depth-write off and source-alpha
   blending. `BlendState` already exists in `rhi/descs.h` and the SDL_GPU backend
   already honours it, so the freeze is untouched here too.
7. **Back-to-front ordering is `extract`'s**, expressed in the existing
   `sortKey`: pass 1 for transparent, and the depth field inverted so ascending
   key order is descending view depth. Inverting at extraction rather than
   reversing at submission keeps "walk the list in order" true in every backend,
   which is M4's third design constraint.
8. **A draw is transparent when its instance alpha or its material's base-colour
   alpha is below one.** Both, because a glTF material can be transparent on its
   own and a script can make an opaque mesh see-through; either alone leaves a
   case that renders wrong.
9. **Shadow snapping is in light space, at texel granularity.** Extent and
   resolution are compile-time constants, so the increment is one too. The box is
   centred on the camera, which sits at the snapshot's origin, so what is snapped
   is the light-space position of that origin.
10. **`PointLight.Shadows` and `SpotLight.Shadows` stay, marked inert.** Removing
    them would break a familiar shape for a property whose semantics are not in
    doubt — only its implementation date is. What was actually wrong is that
    nothing told the person clicking it. That is Decision 11.
11. **The IDL gains `Inert`**, a property-level declaration meaning "backed,
    stored, read back faithfully, and nothing acts on it yet". It flows to
    `PropertyDesc`, to the inspector as a visible tag, and to the api-dump. The
    schema requires `Native` alongside it, because a property with no `Native` is
    already declared-not-backed and two markers for one idea would confuse.
12. **`Model.PrimaryPart` is not inert, and the ledger was wrong about it.**
    `instance_binding.cpp`'s `modelPivot` reads it: with a primary part
    `GetPivot` returns that part's `CFrame` and `PivotTo` moves the model about
    it. The finding is that nobody had tested the consuming branch, so the
    property looked unread from every angle anyone checked. A test, not a marker.
13. **The log file sink's path is injected by `app`.** `core` is L0 and
    `platform::paths()` is L1. The console sink is unchanged and the file is an
    addition: every gate and the conformance runner read stdout.
14. **The crash handler lives in `platform`**, for the same reason the SDL seam
    does — it is per-OS code — and is installed by `app` at boot.
15. **Human-reported defects get a numbered registry, `docs/defects.md`**, and
    the docs gate enforces that the numbering has no holes. That is what makes
    losing one visible: a close-rewrite of `PROGRESS.md` can drop a bullet, and it
    cannot drop a row without leaving a gap the gate names.
16. **The deliverable gains one transparent object.** The roadmap's "unchanged as
    source" means the fix is the engine's rather than the example's; it cannot
    mean the deliverable demonstrates a fade with nothing that fades.

## Build order

1. `Lighting` from boot, the host test, the api-design correction. Everything
   else is downstream, and every artifact recorded before it is wrong.
2. The differential gate: environment equality in `render_world_tests`, id
   resolution in `world_host_tests`, and the two-clock capture pair as a CTest.
3. Shadow texel snapping.
4. `Transparency`: the field, the uniform, the pass, the sort, the shader.
5. The `Inert` marker: schema, generator, descriptors, inspector, api-dump; the
   two `Shadows` properties marked; the `PrimaryPart` consumer test.
6. The log file sink, then the crash handler; then attempt the `Size`/`CFrame`
   reproduction with the handler in place.
7. `docs/defects.md` and its gate; the `architecture.md` §app audit.
8. Re-record: goldens, lavapipe, the 1080p baseline, the day-strip.
9. Full gate, Gate Record, ledger. Stop for the human.
