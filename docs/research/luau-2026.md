# Luau Language & Runtime — State of the Art, August 2026

Research current as of 2026-08-19. All dates/versions verified against primary sources (GitHub API, luau.org, rfcs.luau.org) unless flagged in the final section.

---

## 0. Orientation: what changed since Jan 2026

Three things matter most for a new engine and are **newer than a Jan-2026 knowledge cutoff**:

1. **Luau now has non-`number` primitive types in the VM.** `LUA_TINTEGER` (64-bit int) and `LUA_TCLASS` / `LUA_TOBJECT` (nominal classes) are in `lua.h` on master. This is the biggest ABI/semantic change in years.
2. **The new type solver is the default** in open-source `luau-analyze` (opt out with `--solver=old`), and went GA on Roblox 2025-11-20.
3. **Domain moved to `luau.org`** (`luau-lang.org` redirects). RFCs live at `rfcs.luau.org`.

### Breaking changes to the C++/C embedding API, 2025–2026

Ranked by impact on a host:

1. **New value types in `lua_Type`** (master). Verbatim from `VM/include/lua.h`:
   ```c
   enum lua_Type {
       LUA_TNIL = 0, LUA_TBOOLEAN = 1, LUA_TLIGHTUSERDATA, LUA_TNUMBER,
       LUA_TINTEGER, LUA_TVECTOR,   /* LUA_TVECTOR here when LUA_VECTOR_DOUBLE == 0 */
       LUA_TSTRING, LUA_TTABLE, LUA_TFUNCTION, LUA_TUSERDATA, LUA_TTHREAD,
       LUA_TBUFFER, LUA_TCLASS, LUA_TOBJECT,
       /* LUA_TVECTOR here instead when LUA_VECTOR_DOUBLE == 1 */
       LUA_TDEADKEY, LUA_TPROTO, LUA_TUPVAL, LUA_T_COUNT = LUA_TDEADKEY
   };
   ```
   → **Any host `switch` on `lua_type()` must handle `LUA_TINTEGER`, `LUA_TCLASS`, `LUA_TOBJECT`.** Note `LUA_TVECTOR`'s ordinal **moves** depending on `LUA_VECTOR_DOUBLE` — enum values are not stable across build configs. Do not persist type tags.
2. **`Luau::CompileOptions` / `lua_CompileOptions` grew fields** (see §4) — `vectorPrecision`, `librariesWithKnownMembers`, `libraryMemberTypeCb`, `libraryMemberConstantCb`, `disabledBuiltins`, `userdataTypes`. Struct is not ABI-stable; recompile the host with matching headers.
3. **0.725: C API now auto-reserves stack slots.** Manual `lua_checkstack` calls become redundant (harmless but dead). Behavior change, not a compile break.
4. **0.732: C closure debug name type changed** `const char* → TString*` — affects hosts poking at internals.
5. **0.698: `Luau.Require` `is_config_present` → `get_config_status`** (returns `CONFIG_ABSENT / AMBIGUOUS / PRESENT_JSON / PRESENT_LUAU`). Hard break for anyone who adopted Require early.
6. **0.671: Analysis API `ClassType` → `ExternType`**, and `declare class` → `declare extern type` in `.d.luau` files. **If you ship engine type definitions, this is a required migration.** `extern class` was fully disallowed in 0.727 (2026-06-26).
7. **0.731: `lua_unref` now consistently returns `LUA_NOREF`**; stack-overflow error reporting unified.
8. **0.673: 32-bit builds unblocked** (a `static_assert` was removed).

**Build requirements:** C++11 for `Luau.VM`; C++17 for `Luau.Compiler` / `Luau.Analysis`. CMake ≥ 3.10 (raised in 0.668). MSVC 2017+, gcc-7+, clang-7+.

## 2. Type system

### New Type Solver (NTS) — status

- **Open source `luau-analyze`: NTS is the DEFAULT.** `CLI/src/Analyze.cpp` exposes `--solver=old` to select the legacy checker. Also `--mode=strict` (default nonstrict), `--formatter=plain|gnu`, `-j<N>`, `--annotate`, `--timetrace`, `--logbase=<path>`, `--fflags=<flags>`.
- **Roblox GA: 2025-11-20** — https://devforum.roblox.com/t/general-release-luau%E2%80%99s-new-type-solver/4084991
  - Auto-enabled for **`nocheck` and `nonstrict`** users.
  - **`strict` mode remained opt-in** at GA, explicitly because of "known correctness bugs."
  - Old solver "remains available through 2026."
  - Acknowledged issues at GA: **verbose/large error messages**, and **excessive memory usage**.
- Internal flag is `FFlag::LuauSolverV2` (renamed from `DebugLuauDeferredConstraintResolution` in 0.641).
- **EqSat / e-graph based simplification was deleted in 0.702 (2025-12-02)** as an unsuccessful experiment — worth knowing if you read older design docs.

### How well does strict typing work for large codebases in 2026? — honest read

- Direction of travel through 2026 releases is *relentless bug-fixing of NTS*, not new capability. Nearly every weekly release 0.696→0.734 has multiple "fix crash / fix false positive / fix ICE in new solver" entries. Fuzzer-found crashes were still being fixed as recently as 0.715, 0.725, 0.726.
- Known-real problems reported by users: **memory blowup** on large script counts (https://devforum.roblox.com/t/new-luau-type-solver-causing-extremely-high-memory-usage/4110630), and turning on strict mode on an existing large codebase produces a large error wave.
- Mitigations that landed: fuel-based normalization limits (0.698), stack-overflow guards in `Unifier2` (0.700), native stack guards Win/macOS (0.697), `Frontend::clearModules()` for selective invalidation (0.730), analysis perf work (0.696, 0.702).
- **Engineering read for a new engine:** greenfield + strict-by-default is viable and is the recommended posture (no legacy error wave). Budget for: (a) analyzer memory/time in CI at scale, (b) occasional ICEs, (c) pinning a Luau version and upgrading deliberately rather than tracking weekly.

### Type functions

- **Built-in type functions:** `keyof`, `rawkeyof`, `index`, `rawget`, `setmetatable`/`getmetatable` type functions, `never`/`unknown`, negation types, read-only (`read`) and write-only (`write`) properties.
- **User-defined type functions (UDTFs) — Implemented.** Syntax `type function f(...) end`, invoked as `f<A, B>`.
  - Run in an **isolated VM** at analysis time. Available globals: `assert`, `error`, `print`, iteration builtins, type introspection, `pcall`/`xpcall`, plus `math`, `table`, `string`, `bit32`, `utf8`, `buffer`.
  - `types` library: `types.unknown/never/any/boolean/number/string`, `singleton()`, `negationof()`, `unionof()`, `intersectionof()`, `newtable()`, `newfunction()`, `copy()`, `optional()`; per-tag instance methods.
  - Timeouts use analysis-level runtime limits (no infinite-loop detection).
  - **RFC #228 (merged 2026-08-03, shipped 0.734): error handling** — `error()` inside a UDTF surfaces as a type-analysis diagnostic, so you can author custom type-level error messages. `pcall`/`xpcall` now allowed.
  - RFCs: https://rfcs.luau.org/user-defined-type-functions.html · generic types & packs in UDTFs · thread/buffer types in UDTFs · `udtf-is-extern` · `types.optional` · `type:issubtypeof` (0.724)
- **Explicit type-parameter instantiation** — RFC implemented 0.701, production-ready 0.704.

### Modes

`--!nocheck` / `--!nonstrict` (default) / `--!strict`, overridable per-directory via `.luaurc` `languageMode` or `.config.luau` `languagemode`.

## 3. Native codegen (NCG)

### Status & platforms

- **X64 (AVX1+) and A64 (arm64) — fully supported, out of "Preview" as of the 2025 recap** (https://luau.org/news/2025-12-19-luau-recap-runtime-2025/).
- **Android support added and production-tested** (stated in that same 2025 recap).
- **iOS: not available.** Apple prohibits runtime code generation for App Store apps (W^X). Luau falls back to the interpreter. This was historically a core reason Roblox avoided a JIT at all.
- Non-supporting hardware silently falls back to interpretation — `luau_codegen_supported()` returns 0.
- Positioning: **hybrid AOT/JIT** — it compiles *already-loaded bytecode*, function-granular, on demand. **No runtime type feedback / no trace recording** — it relies on source-level type annotations and compiler-emitted type info. This is the single most important architectural fact: *NCG performance is a function of how well-typed your Luau is.*

### How to enable when embedding

C API (`CodeGen/include/luacodegen.h`, verbatim):
```c
LUACODEGEN_API int  luau_codegen_supported(void);
LUACODEGEN_API void luau_codegen_create(lua_State* L);
LUACODEGEN_API void luau_codegen_compile(lua_State* L, int idx);
```
C++ API (what the official REPL uses, `CLI/src/Repl.cpp`):
```cpp
if (codegen) Luau::CodeGen::create(L);              // once, right after luaL_newstate
...
std::string bytecode = Luau::compile(source, copts());
if (luau_load(L, chunkname.c_str(), bytecode.data(), bytecode.size(), 0) == 0) {
    if (codegen) {
        Luau::CodeGen::CompilationOptions nativeOptions;
        if (codegenCold) nativeOptions.flags = Luau::CodeGen::CodeGen_ColdFunctions;
        Luau::CodeGen::compile(L, -1, nativeOptions);   // compiles target fn + all inner fns
    }
}
```
Required: link `Luau.CodeGen` (in addition to `Luau.VM`, `Luau.Compiler`, `Luau.Ast`, `Luau.Common`). Compile with `typeInfoLevel = 1` (the REPL hardcodes this) so NCG has type info.

Opt-in granularity: `--!native` (whole script) and the **`@native` function attribute** (RFC implemented; non-recursive — inner functions need their own attribute).

Also new: **0.727 (2026-06-26) added a bytecode→bytecode JIT inliner** (`Luau::JitInliner::setup(L)`, CLI `--jit-inliner`) — separate from NCG, operates on bytecode. Plus 0.724 added bytecode-level call inlining in the compiler.

### Measured gains

Only official numbers I could find are the 2023 Roblox announcement (still the canonical figures; **no newer measured numbers published**):
- **~1.5×–2.5×** for compute-heavy functions.
- **3.2×** on a developer's Mandelbrot implementation.
- Third-party (Are-we-fast-yet, HN Oct 2025): Luau + partial native ≈ **1.6× slower than LuaJIT in JIT mode**; Luau interpreter ≈ **parity with LuaJIT's interpreter**.

**Does NOT help:** top-level scope code, code dominated by library/host-API calls, untyped code, `getfenv`/`setfenv` usage, non-numeric args to math builtins. Breakpoints disable native execution for that function. NCG costs extra memory (tracked under a `lua/codegen` memory category).

2025–2026 NCG work landed: vector native lowering with `MULADD_NUM` (FMA), `EXTRACT_VEC`, hardware dot-product; branchless `==`/`~=` and type checks; `CMP_INT`, `SELECT_IF_TRUTHY`, `GET_CACHED_IMPORT`; load-store propagation extended to upvalues/buffers/userdata; **NCG plugins that extend native codegen to embedder-defined types**.

## 4. Embedding workflow (C++ host)

### Pipeline

```
source (.luau)
  → Luau::compile / luau_compile   [Luau.Compiler, C++17]
  → bytecode (opaque std::string / char*)
  → luau_load(L, chunkname, data, size, env)   [Luau.VM, C++11]
  → (optional) Luau::CodeGen::compile(L, -1, opts)
  → lua_pcall / luaL_pcallyieldable
```

`Compiler/include/luacode.h`, verbatim:
```c
struct lua_CompileOptions {
    int optimizationLevel;      // default=1
    int debugLevel;             // default=1
    int typeInfoLevel;          // default=0
    int coverageLevel;          // default=0
    const char* vectorLib;
    const char* vectorCtor;
    const char* vectorType;
    int vectorPrecision;        // default=0
    const char* const* mutableGlobals;
    const char* const* userdataTypes;
    const char* const* librariesWithKnownMembers;
    lua_LibraryMemberTypeCallback  libraryMemberTypeCb;
    lua_LibraryMemberConstantCallback libraryMemberConstantCb;
    const char* const* disabledBuiltins;
};
LUACODE_API char* luau_compile(const char* source, size_t size,
                               lua_CompileOptions* options, size_t* outsize);
```
Engine-relevant knobs:
- `optimizationLevel = 2` enables **function inlining + loop unrolling**.
- `typeInfoLevel = 1` required for NCG to be effective.
- `vectorLib`/`vectorCtor`/`vectorType`/`vectorPrecision` let the compiler **constant-fold and fastcall your host vector constructor** (e.g. `Vector3.new`) — critical for a game engine.
- `mutableGlobals` — tell the compiler which globals the host may mutate (otherwise it assumes builtins are immutable, which is what `safeenv` guarantees).
- `userdataTypes` + `librariesWithKnownMembers` + the two callbacks — feed host type knowledge into the compiler so NCG can specialize on engine userdata.
- `disabledBuiltins` — strip builtins you don't ship.

You can **ship the VM without the compiler**: precompile to bytecode offline and only link `Luau.VM` in the shipping client. `luau-compile` CLI exists for this.

### C API vs Lua 5.1 API

"An extended version of Lua's C API," backwards-compatible with Lua 5.1 *in spirit*, with concrete deviations. See https://luau.org/compatibility/

**Removed/absent vs Lua 5.1:** `io`, `os` (mostly), `package`, most of `debug`; `loadfile`, `dofile`, `loadstring` on bytecode, `string.dump`; `newproxy` restricted.
**Absent vs 5.2:** `goto`, `__gc`, ephemeron tables, yieldable metamethods, `__pairs`/`__ipairs` (Luau uses `__iter`).
**Absent vs 5.3:** 64-bit integers *as `number`*, bitwise operators (use `bit32` — but see the new `integer` library, §5).
**Absent vs 5.4:** to-be-closed vars, `__gc`, generational GC.
**Also absent: proper tail calls** — deliberately removed (debuggability + bytecode verification).

**Luau-only C API you will actually use** (`VM/include/lua.h`):
```c
/* interrupts / hooks — the game-loop safety valve */
struct lua_Callbacks {
    void* userdata;
    void (*interrupt)(lua_State* L, int gc);
    void (*panic)(lua_State* L, int errcode);
    void (*userthread)(lua_State* LP, lua_State* L);
    int16_t (*useratom)(lua_State* L, const char* s, size_t l);
    void (*debugbreak)(lua_State* L, lua_Debug* ar);
    void (*debugstep)(lua_State* L, lua_Debug* ar);
    void (*debuginterrupt)(lua_State* L, lua_Debug* ar);
    void (*debugprotectederror)(lua_State* L);
    void (*onallocate)(lua_State* L, size_t osize, size_t nsize);
};
lua_Callbacks* lua_callbacks(lua_State* L);
```
> Callbacks are **shared between all coroutines** of a state. `interrupt` is documented as **safe to set from an arbitrary thread**; all others require the VM to be idle. `userthread` fires on coroutine create (`LP == parent`) and destroy (`LP == NULL`) — this is your hook for per-coroutine host data.

Timeout enforcement = set `interrupt`; it fires at function calls and loop back-edges. Roblox uses a 10s Studio script limit built on this. There is **no default memory limit** — you impose it in your `lua_Alloc`.

**Allocator / memory:**
```c
typedef void* (*lua_Alloc)(void* ud, void* ptr, size_t osize, size_t nsize);
lua_State* lua_newstate(lua_Alloc f, void* ud);   // luaL_newstate() = default allocator
lua_Alloc  lua_getallocf(lua_State* L, void** ud);
void   lua_setmemcat(lua_State* L, int category);     // LUA_MEMORY_CATEGORIES = 256
size_t lua_totalbytes(lua_State* L, int category);
int64_t lua_allocationrate(lua_State* L);             // NEW 0.731 — for external GC pacing
void   lua_memorydump(lua_State* L, void* file, lua_CategoryName categoryName);  // NEW 0.731
```
Luau's built-in allocator (paged, size-classed, `LUA_SIZECLASSES = 40`) is documented as outperforming jemalloc/tcmalloc for this workload — benchmark before replacing it.

**GC control:** `lua_gc(L, what, data)` with `LUA_GCSTOP, LUA_GCRESTART, LUA_GCCOLLECT, LUA_GCCOUNT, LUA_GCCOUNTB, LUA_GCISRUNNING, LUA_GCSTEP, LUA_GCSETGOAL, LUA_GCSETSTEPMUL, LUA_GCSETSTEPSIZE, LUA_GCISPAUSED` (last one new in 0.731).

**Userdata (your engine objects):**
```c
void* lua_newuserdatatagged(lua_State* L, size_t sz, int tag);
void* lua_newuserdatataggedwithmetatable(lua_State* L, size_t sz, int tag); // ~3x faster creation
void  lua_setuserdatadtor(lua_State* L, int tag, lua_Destructor dtor);      // tag dtors replace __gc
void  lua_setuserdatatag(lua_State* L, int idx, int tag);
```
`LUA_UTAG_LIMIT = 128`, `LUA_LUTAG_LIMIT = 128`. **There is no `__gc`** — tag-based destructors are the host-only replacement, and they're safer and faster.

**Other useful:** `lua_clonetable`, `lua_cpcall`, `luaL_pcallyieldable` (0.725), `luaL_callyieldable`, `lua_rawgetp/rawsetp/rawgetptagged/rawsetptagged` (0.699, lightuserdata indexing), `lua_setthreaddata`/`lua_getthreaddata`, `lua_resetthread`/`lua_isthreadreset` (coroutine pooling), `lua_tolstringatom` + `useratom` (string interning for fast property dispatch), `lua_atbreakpoint`/`lua_callhook`/`lua_setpointerencodekey`/`lua_hascustomexecution`/`lua_incustomexecution` (all promoted to public in 0.731 — this is the **debugger-authoring surface**, relevant if you want a Studio-like debugger).

### Sandboxing model

https://luau.org/sandbox/ + README.
- Call **`luaL_sandbox(L)`** on the main state and **`luaL_sandboxthread(L)`** per script thread. This enables the **`safeenv`** optimization (the README explicitly calls it "the recommended `safeenv` security feature") — it's simultaneously a security *and* a performance feature, because it lets the compiler/VM assume builtins are immutable and use import fastpaths.
- Effects: all library tables (`string`, `math`, …), the string metatable, and `_G` are marked **readonly**; each script gets its **own global table** chained via `__index` to the protected builtins.
- Unsafe libs are simply **not compiled in** (`io`, `package`, most of `os`/`debug`, `loadfile`/`dofile`/`string.dump`, bytecode loading via `loadstring`).
- **Docs still recommend separate VMs for guaranteed isolation** between mutually-untrusted code.
- No `__gc` by design (memory-safety + perf).
- Bytecode loading from untrusted sources: bytecode is *verified* on load, but the safe posture is to only load bytecode you compiled.

`luaconf.h` tunables you'll want to review: `LUA_VECTOR_SIZE` (3 or 4, default 3), `LUA_VECTOR_DOUBLE` (0/1), `LUAI_MAXCSTACK 8000`, `LUAI_MAXCALLS 20000`, `LUA_SIZECLASSES 40`, `LUA_MEMORY_CATEGORIES 256`, `LUA_UTAG_LIMIT 128`, `LUA_LUTAG_LIMIT 128`.

### Multi-VM / multithreading — **you must build your own**

This is unambiguous and hasn't changed:

> "Luau currently requires the host to ensure exclusive access to different VMs (aka top-level `lua_State`)… Separate coroutines that belong to the same state can not be executed or worked with concurrently, as internal components of the VM such as the garbage collector are not thread-safe."
> — zeux (Arseny Kapoulkine), https://github.com/luau-lang/luau/discussions/311, 2022-02-02

- `lua_newthread` = **coroutine**, not OS thread.
- **Roblox's Parallel Luau / Actors is a Roblox-engine feature, not part of open-source Luau.** Its architecture is exactly: many lightweight VMs, one script per VM, host-side message passing that **unmarshals Luau values out of VM A and re-marshals into VM B**, plus shared access to the C++ DataModel. Roblox's own docs describe the VM as "fairly lightweight to instantiate which makes running many VMs per core practical."
- **Implication for your engine:** you get to (and have to) design this yourself. The recipe Roblox validated: `lua_State*` per worker thread, an allocator per VM (or a thread-safe one), a serialization/marshalling layer for cross-VM values, a job queue, and shared C++ state guarded by your own locks. `lua_setthreaddata` + the `userthread` callback are the hooks for binding host-side context to coroutines/VMs. `lua_allocationrate` (0.731) exists specifically so a host can pace GC externally across many VMs.

## 5. Language features that landed recently

### Require-by-string (module resolution outside Roblox)

Fully specified and **implemented**; there is a dedicated **`Luau.Require`** library for embedders (introduced 0.669, 2025-04-12; `Luau.RequireNavigator` folded in at 0.698).

**Semantics** (https://rfcs.luau.org/amended-require-resolution.html — status: Implemented):
- Every require string **must** start with `@` (alias), `./`, or `../`. **Unprefixed paths are an error.** The old `paths` array is removed.
- Resolves `.luau` and `.lua`; a directory with `init.luau`/`init.lua` is requirable as a module.
- Errors on ambiguity: both `.lua` and `.luau` present; or `module.luau` *and* `module/init.luau` present.
- **`init.luau` relative requires resolve from the parent directory** (Rojo-compatible). To reach your own children from `init.luau`, use the reserved **`@self/foo`** alias (RFC #215, merged 2026-07-17, shipped 0.731). `@self` cannot be overridden by user aliases.
- **Cyclic requires supported** (RFC #205, merged 2026-06-02): "tie-the-knot" — the cycle-participant receives a placeholder export table via `...`; a `CyclicDependencyError` metatable blocks top-level reads/writes until population completes. Access from inside function bodies is fine. C API: `luarequire_createplaceholder`, `luarequire_lockplaceholder`, `luarequire_populateplaceholder`.

**`.luaurc`** (JSON, cascades up the directory tree; nearer files override):
```jsonc
{
  "languageMode": "strict",           // "nocheck" | "nonstrict" | "strict"
  "lint": { "*": true, "LocalUnused": false },
  "lintErrors": false,                 // default false → warnings
  "typeErrors": true,                  // default true → errors
  "globals": ["expect"],               // treated as `any` globals
  "aliases": { "libs": "./vendor", "engine": "/abs/path" }
}
```
Alias rules: `@name` prefix only, charset `[A-Za-z0-9.\-_]`, case-insensitive, no `/` or `\` in the name, matches only at path start, supports submodules (`@Roact/createElement`), **inherited from parent `.luaurc` and overridable**, relative alias targets resolve relative to the defining `.luaurc`, **alias chains resolve iteratively with cycle detection** (0.700 / RFC #145), `@` alone is reserved.

**`.config.luau`** — NEW, RFC #125 merged 2025-10-22, implemented 0.698. Luau-syntax alternative to `.luaurc` (fields lowercased: `languagemode`, `lint`, `linterrors`, `typeerrors`, `globals`, `aliases`). Executed in an **isolated VM with a 2-second timeout**, so it can contain variables/functions/loops. **Having both `.luaurc` and `.config.luau` in one directory is an error.** Motivation was explicitly "embedders who lack natural JSON support." 0.732 added parsing configs **from bytecode** rather than source.

**Embedder API** — `Require/include/Luau/Require.h`. You implement a `luarequire_Configuration` vtable of callbacks and Luau does the rest:
- `is_require_allowed`
- navigation: `reset`, `to_parent`, `to_child`, `jump_to_alias`
- `is_module_present`
- identity: `get_chunkname`, `get_loadname`, `get_cache_key`
- config: `get_config_status`, `get_config`, `get_alias`, `get_luau_config_timeout`
- alias hooks: `to_alias_override`, `to_alias_fallback`
- `load` (executes the module, returns stack results)

Enums: `luarequire_NavigateResult {NAVIGATE_SUCCESS, NAVIGATE_AMBIGUOUS, NAVIGATE_NOT_FOUND}`, `luarequire_WriteResult {WRITE_SUCCESS, WRITE_BUFFER_TOO_SMALL, WRITE_FAILURE}`, `luarequire_ConfigStatus {CONFIG_ABSENT, CONFIG_AMBIGUOUS, CONFIG_PRESENT_JSON, CONFIG_PRESENT_LUAU}`.

Functions: `luaopen_require`, `luarequire_pushrequire`, `luarequire_pushproxyrequire`, `luarequire_registermodule` (pre-register a host module under an alias — this is how you expose engine APIs as `require("@engine/render")`), `luarequire_clearcacheentry`, `luarequire_clearcache`, plus the three placeholder fns.

`Require/include/Luau/RequireNavigator.h` gives static tooling (analyzer/LSP) the same resolution without executing.

> **This is a big deal for your engine:** you can give developers a real filesystem module system with npm-like aliases, and get identical resolution in the runtime, `luau-analyze`, and luau-lsp — no Rojo, no Roblox DataModel.

### `vector` — the built-in primitive

- **Genuinely a VM primitive** (`LUA_TVECTOR`), not userdata. Immutable (component writes unsupported).
- **`LUA_VECTOR_SIZE`: 3 by default, "must be 3 or 4."** In 4-wide mode a `w`/`W` component appears. Components accessible as `x`/`X`, `y`/`Y`, `z`/`Z`, `w`/`W`.
- **`LUA_VECTOR_DOUBLE`: 0 by default (f32). Set to 1 for f64** — added 0.731 (2026-07-24). **Double vectors are heap-allocated** (they no longer fit in the inline value), so they are GC-managed and slower than the f32 packed representation. Bytecode version was bumped in 0.732 to carry double-precision vector constants.
- **`vector` library** (added during 2025; RFC https://rfcs.luau.org/vector-library.html): `vector.zero`, `vector.one`, `vector.create(x,y,z[,w])`, **`vector.create(x,y)`** (2-component overload, Implemented — zero-fills z/w), `magnitude`, `normalize`, `cross`, `dot`, `angle(a,b[,axis])`, `floor`, `ceil`, `abs`, `sign`, `clamp`, `max(...)`, `min(...)`, `vector.lerp` (RFC).
- Compiler support: vector **constants**, constant folding, fastcall; NCG lowers to SIMD with `MULADD_NUM` (FMA), `EXTRACT_VEC`, and hardware dot-product instructions.
- Host integration: `vectorLib`/`vectorCtor`/`vectorType`/`vectorPrecision` compile options let you map `Vector3.new(...)` onto the primitive with folding.

> **Engine decision point:** 3-wide f32 is the fast path and the default everywhere. 4-wide costs 33% more memory per value on every vector; f64 makes vectors heap objects. Recommend 3-wide f32 unless you have a hard requirement. Also note: `LUA_VECTOR_DOUBLE` changes the `lua_Type` enum ordering — treat it as an ABI-defining flag decided once, up front.

### `buffer` — resizable-free binary blob

Primitive type `LUA_TBUFFER`. `buffer.create(size)` (max 1 GB, zero-init), `fromstring`, `tostring`, `len`, `readi8/u8/i16/u16/i32/u32/f32/f64`, matching `write*`, `readstring`/`writestring`, **`readbits`/`writebits`** (0–32 bits, added 2025), `copy`, `fill`. **Little-endian, two's complement.** NCG has native lowering for buffer access with bounds-check merging (0.732). This is your zero-copy interop path for mesh/particle/network data.

### 64-bit integers — **NEW in 2026**

- RFC #153 merged **2026-02-12**; improvements #176 (2026-02-16), #182 (2026-03-25). **Initial implementation shipped in 0.715 (2026-04-03)**, described as still bug-finding and possibly RFC-amending. `VM/src/lintlib.cpp`, `luaopen_integer`/`LUA_INTLIBNAME`, conformance tests `integers.luau` + `integers_regspill.luau` + `native_integer_spills.luau` all present on master.
- Distinct type `integer` (`LUA_TINTEGER`), signed two's-complement 64-bit. **Literal suffix**: `123i`, `1_000i`, `0xABABi`, `0b1000_1000i`; `-123i` allowed when unary minus is directly applied.
- **No arithmetic operators and no implicit conversion with `number`** — everything is library calls: `integer.add/sub/mul/div/rem/mod`, `band/bor/bxor/bnot/lshift/rshift/arshift/lrotate/rrotate/extract/replace`, `lt/le/gt/ge` + unsigned `ult/ule/ugt/uge`, `min/max/clamp/countrz/countlz/bswap`, `create/fromstring/tonumber`.
- C API: `lua_pushinteger64`, `lua_tointeger64(L, idx, int* isinteger)`, `lua_isinteger64`, `luaL_checkinteger64`, `luaL_optinteger64`.
- 0.728 (2026-07-03) fixed **rare data corruption in mod/div/rem** — treat as maturing, not mature.

> Relevant to an engine for: entity IDs, network IDs, hashes, timestamps, file offsets — all previously painful in a doubles-only language.

### Classes — **NEW in 2026**

- RFC #191 "Classes!!" merged **2026-04-27** (most-reacted RFC on the repo, 198 reactions). https://rfcs.luau.org/syntax-classes.html
- Implementation exists on master: `VM/src/lclass.cpp`, `lclass.h`, `lclasslib.cpp`, `luaopen_class`/`LUA_CLASSLIBNAME`, `LUA_TCLASS`/`LUA_TOBJECT`, conformance test `tests/conformance/classes.luau`.
- **Nominal** types (unlike tables, which are structural). Top-level only. Fields via new contextual keyword `public`; methods via `function` (`public function f()` also allowed). Instantiate by calling the class: `Point.new(3,4)` or `Point { x=3, y=4 }`. `self`-first methods use `obj:m()`; others are statics via `Class.m()`. Class identifiers hoisted to module scope. Metamethods supported (`__add`, `__tostring`, …).
- New `class` global library: `class.isinstance()`, `class.classof()`. `type()`/`typeof()` return `"class"` for the class object and `"object"` for instances.
- **Out of scope for now:** private fields, generic classes, **inheritance** (deferred to future RFCs). RFC #244 (merged 2026-08-17) already tweaks `__eq` "in the face of inheritance," so inheritance is clearly being worked toward.
- Fallout: `declare class` was deprecated in 0.720 in favor of `declare extern type`, and `extern class` was **disallowed** in 0.727 — the `class` keyword was being freed up for this.
- 0.725 fixed a crash combining `export` and `class`.

### `const` keyword — **NEW in 2026**

RFC #166 merged **2026-02-24**. `const x = 5`, `const x: number = 5`, `const a, b = 1, 2`, `const function f() end`. **Immutable binding, not a compile-time constant, not a deep freeze** — the referenced table stays mutable. Enforced at runtime; compound assignment (`+=`) rejected. In `luau-analyze`/autocomplete by 0.720; **StyLua 2.5.0 formats `const` and `const function`**, which is strong evidence it's real and shipping.

### `export` / export-by-value — **NEW in 2026**

RFC #179 merged 2026-04-27, **implemented in 0.723 (2026-05-29)**. `export local x = ...`, `export const TAU = ...`, `export function init() end` at module top level. Desugars to a table that is **frozen and returned**. Exported functions are always const; duplicate exported identifiers are a parse error; you cannot mix `export` with an explicit `return`. Enables **cross-module inlining and constant folding**.

### Older but still core (confirmed present)

- **String interpolation** — `` `count is {n}` `` (RFC, shipped 2023). 0.720 removed redundant `MOVE` instructions in interp codegen.
- **Generalized iteration** — `for k, v in t` works over tables/arrays and any `__iter`. 0.722 added **yielding iterators**. 0.734 fixed NTS inference for it.
- **`math.lerp`, `math.map`, `math.isnan/isinf/isfinite`** (2025), **math constants** (RFC #169, merged 2026-02-11).
- Attributes: `@native`, `@deprecated` (0.667), `@self`; function attribute parameters RFC.
- `if-then-else` expressions, `continue`, compound assignment, floor division `//`, typed variadics, singleton types, default type-alias params, `table.freeze/clone/clear/create/find`, `string.pack/unpack/packsize`, `bit32.byteswap/countlz/countrz`, `coroutine.close`, `debug.info`.

## 6. Performance characteristics

Primary source: https://luau.org/performance/ ("How we make Luau fast").

### Interpreter
- "A very highly tuned portable **bytecode interpreter written in C**"; "on some workloads it can match the performance of **LuaJIT interpreter**"; "noticeably faster than **Lua 5.x (including Lua 5.4)**."
- Interpreter core ~**16 KB on x64** — deliberately sized to leave half the L1 icache for host code. This matters in a game engine where the host is the icache-hungry party.
- Register-based bytecode, purpose-built multi-pass compiler (not Lua's single-pass), inline caching, **fastcall** for builtins, closure caching, optimized table iteration.
- `-O2` adds function inlining + loop unrolling. 2025–2026 added constant folding for `string.char`, `string.sub`, concatenation and interpolation; propagation of non-literal constants (including functions); per-call inlining cost updates with constant args; operand reordering.
- **Compile throughput: "950K lines of Luau code in 1 second on a single core."**
- Third-party (Are-we-fast-yet, HN Oct 2025): interpreter ≈ LuaJIT interpreter; +NCG ≈ 1.6× slower than LuaJIT JIT; LuaJIT JIT ≈ 10× slower than C99.

### GC — **incremental, non-generational, non-moving, mark-and-sweep**
- Three phases: **mark → atomic → sweep**. Only the atomic step is a stop-the-world-ish pause, once per cycle.
- **Incremental marking of coroutines** to shrink the atomic step (specifically motivated by "many coroutines" workloads — i.e. games).
- **Paged sweeper, "2–3× faster"** than the linked-list sweeper in Lua/LuaJIT.
- Pacing algorithm "inspired by … Go's garbage collector," heap-percentage targeted. Tunable via `LUA_GCSETGOAL` / `LUA_GCSETSTEPMUL` / `LUA_GCSETSTEPSIZE`. GC assists run interleaved with allocation.
- **Generational GC is explicitly NOT implemented** (listed as unsupported vs Lua 5.4).
- `lua_allocationrate` (0.731) added so hosts can pace GC externally.
- **Digital Extremes migrated *Warframe* from its previous Lua to Luau specifically citing improved garbage collection.**

### What a game engine should know
1. **No `__gc`.** Use `lua_setuserdatadtor` per userdata tag. This is faster and avoids resurrect hazards, but it means *finalization is host-controlled only* — scripts can't register cleanup.
2. **No proper tail calls.** Deep recursion / CPS-style script patterns will blow the C stack. `LUAI_MAXCALLS = 20000`.
3. **Numbers are doubles.** Use the new `integer` type for IDs/hashes — but it's library-call-only, so it's not a drop-in for arithmetic-heavy code.
4. **Vectors and buffers are the fast interop path.** Vector is a true primitive with SIMD lowering; buffer is a flat byte block with native bounds-check merging. Design your C++↔Luau boundary around these two, not around tables-of-numbers.
5. **`safeenv` is a perf feature.** Sandboxing (readonly builtins) is what unlocks import fastpaths. Don't skip `luaL_sandbox`/`luaL_sandboxthread` "for speed" — it's backwards.
6. **NCG's value is proportional to type annotations.** No runtime type feedback. Untyped hot loops get little; annotated numeric/vector code gets 1.5–2.5×.
7. **GC pauses**: incremental + paged sweep is frame-friendly, but the atomic step is real. Plan to call `lua_gc(L, LUA_GCSTEP, n)` from your frame loop with a time budget rather than letting assists fire unpredictably, and use 256 memory categories (`lua_setmemcat`/`lua_totalbytes`) for per-subsystem attribution.
8. **VM instantiation is cheap** — Roblox states "running many VMs per core" is practical. This is the sanctioned scaling model.

### Editor / analysis

  - **Runs standalone: `luau-lsp analyze` for CI** (a superset of `luau-analyze` with alias/sourcemap resolution).
  - **For a custom engine:** set `luau-lsp.platform.type` to disable auto-loaded Roblox definitions, then supply `luau-lsp.types.definitionFiles` (your `.d.luau` globals) and `luau-lsp.types.documentationFiles` (JSON docs). `--base-luaurc` / `luau-lsp.server.baseLuaurc` gives a baseline config for external editors. **This is a first-class supported path — you will not need to fork it.**

  - Neovim extension: `lopi-py/luau-lsp.nvim`. Also on Open VSX + Chocolatey. Zed has Luau language support docs.

Auto-discovers `.luaurc` / `.config.luau` up the tree.
- **`luau`** (REPL/runner) and **`luau-compile`** also ship in releases.

### Formatting
- **StyLua — v2.5.2, 2026-05-16** (2.5.1 and 2.5.2 same day, npm-publishing fixes only; **2.5.0** is the real release). https://github.com/JohnnyMorganz/StyLua/releases
  - Luau is enabled in default binaries (all syntax variants built in).
  - 2.5.0 added **`const` and `const function`** support, fixed union/intersection hanging, fixed stray newlines before attribute-prefixed `local function`/`const function`.
  - **Gap:** I found no evidence of StyLua support for the 2026 **`class`/`public`** syntax. Verify before adopting classes as an engine idiom.

### Toolchain managers
- **rokit (rojo-rbx) is the current recommendation.** Latest **v1.2.0, 2025-09-30**; v1.1.0 (2025-08-29) added **native ARM64** across platforms. Reads `rokit.toml` and is **backwards-compatible with `foreman.toml` / `aftman.toml`** (aftman/foreman are mutually incompatible by design).
- **foreman** — Roblox-internal-facing, uncertain community future.
- **aftman** — maintainer no longer active in Roblox tooling. **Do not start new projects on it.**
- `roblox-ts/setup-rokit` and `paradoxum-games/setup-rokit` GitHub Actions exist.

### Package managers
- **pesde — use this for non-Roblox Luau.** https://github.com/pesde-pkg/pesde · https://docs.pesde.dev/
  - Latest **v0.7.3+registry.0.2.3, 2026-03-18** (prior v0.7.2, 2025-12-26).
  - Explicitly "supporting multiple runtimes including Roblox and Lune"; **"designed to prevent runtime lock-in"**; manages separate package sets per runtime target (roblox / lune / luau).
  - Sources: its own registry **plus Wally registries plus git repos**.
  - Inspired by npm/pnpm/Wally/Cargo. Installable via toolchain manager.
  - 0.7.3 added **type-function re-exports via dependency linkers** — meaningful for typed libraries.
- **Wally (UpliftGames) — effectively frozen for standalone use.** Last stable **v0.3.2, 2023-06-05**; only a `nightly` tag since (2025-04-14). Roblox/Rojo-shaped (installs into a Roblox instance tree). **Not the right choice for a filesystem-based engine**, though pesde can consume Wally packages.
- **Lute** has stated intent to eventually ship its own package manager.

### Standalone runtimes (reference implementations to steal from)
- **Lute (luau-lang/lute) — official, from the Luau team.** https://lute.luau.org/ · https://github.com/luau-lang/lute
  - **1.0.0 released ~April 2026** (HN discussion 2026-04-26); repo publishes **daily nightlies**, latest `v1.0.1-nightly.20260819` (2026-08-19), tracking Luau 0.734/735. Binaries for Linux x86_64/aarch64, macOS aarch64, Windows x86_64.
  - Node/Deno-shaped: filesystem, HTTP networking (libcurl), process management, crypto (libsodium), event loop (libuv), **plus APIs to manipulate Luau's own syntax tree** (the differentiator — enables codemods/linters written in Luau).
  - Modules exposed via `@std` alias; three layers: `lute` (C++ core), `std` (Luau stdlib, embedded in the binary), `batteries` (standalone Luau libs).
  - **CLI includes a test runner, a linter, and the Luau type checker.**
  - **Strategically important:** "we're working hard to ensure the Roblox game engine will support this same set of `@std` APIs in the future." If you want a Roblox-style DX, **implementing `@std`-compatible APIs in your engine is the alignment play.** Its C++ source is the best available worked example of a non-Roblox Luau host (`Luau.Require` wiring, event loop, VM lifecycle).
  - Caveat: maintainers say "Lute is not a finished product."
- **Lune (lune-org/lune)** — the older community standalone runtime; more Roblox-flavored APIs.

### Test frameworks that run on standalone Luau
Honest summary: **there is no dominant one, and none of them target the bare `luau` CLI as the primary case.**
- **Lute's built-in test runner** — from the Luau team, ships in the CLI. Most likely to become the default. **Best bet if you align with `@std`.**
- **tiniest (dphfox)** — https://github.com/dphfox/tiniest — minimal, portable, zero deps, plugin-based; pre-configured bundles for **Roblox and Lune**; you assemble your own bundle for another runtime. ~42 commits; low but nonzero activity. Snapshot testing included.
- **frktest (itsfrank)** — https://github.com/itsfrank/frktest — "runtime-agnostic" but needs a runtime shim for colored output; **ships shims for Lune, Zune, Lute**. v0.0.2 on Wally + pesde. Author frames it as "for a time when there were no alternatives for Lune."
- **jest-lua** — the heavyweight option; Roblox-oriented, referenced as the step up from frktest.

> **Recommendation for the engine:** expose a `@std`-shaped I/O surface (or at minimum a print/exit/fs shim), then either vendor `tiniest` (zero deps, easiest to port) or run tests under Lute in CI and only run gameplay tests in-engine.

### Other
- **darklua** has a documented "Luau require mode" that resolves `.luaurc` — useful for bundling.
- **Godot binding exists**: GDLuau (Luau C/C++ API bindings), Godot Asset Library #2044 — worth reading for an example of exposing an engine object model.
